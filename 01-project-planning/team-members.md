# Pembagian Tugas dan Tanggung Jawab

## 1. Member 1 — QA Lead / Koordinator Proyek

**Fokus Utama:** Perencanaan dan koordinasi proyek pengujian.

### Materi yang Perlu Dipelajari
1. Pengertian Software Quality Assurance (QA) dan Software Testing.
2. Software Testing Life Cycle (STLC).
3. Tahapan proses pengujian perangkat lunak.
4. Test Plan dan Testing Scope.
5. Dasar ISO/IEC/IEEE 29119-1:2022.

### Tanggung Jawab
1. Mengoordinasikan keseluruhan kegiatan proyek.
2. Menentukan tujuan, ruang lingkup, dan jadwal pengujian bersama tim.
3. Membagi tugas dan memantau perkembangan setiap anggota.
4. Memastikan proses pengujian berjalan sesuai rencana.
5. Meninjau dan menggabungkan hasil pekerjaan anggota.
6. Memastikan seluruh target proyek selesai tepat waktu.

### Target Hasil Pekerjaan
- Gambaran Umum Proyek.
- Ruang Lingkup Pengujian.
- Test Plan.
- Laporan Perkembangan Proyek.

---

## 2. Member 2 — Standards & Literature Research

**Fokus Utama:** Penelitian standar, referensi, dan landasan teori pengujian.

### Materi yang Perlu Dipelajari
1. Pengertian dan tujuan standar ISO/IEC/IEEE dalam software testing.
2. ISO/IEC/IEEE 29119-1:2022.
3. Standar lain yang relevan dengan pengujian perangkat lunak.
4. Konsep Black Box Testing, Equivalence Partitioning, dan Boundary Value Analysis.
5. Materi perkuliahan yang berkaitan dengan pengujian perangkat lunak.

### Sumber Belajar dan Referensi
- Google Scholar.
- Website resmi ISO dan IEEE.
- Jurnal atau penelitian terkait QA tahun 2022–2026.
- Dokumen ISO yang tersedia.
- Materi perkuliahan.

### Tanggung Jawab
1. Mempelajari dokumen standar ISO/IEEE yang tersedia.
2. Mencari referensi pendukung yang relevan dan dapat diakses.
3. Mengidentifikasi bagian standar yang dapat diterapkan dalam proyek.
4. Mengumpulkan referensi beserta tautan, tahun, dan informasi publikasinya.
5. Membuat pemetaan antara standar dan aktivitas pengujian proyek.

### Target Hasil Pekerjaan
- Tinjauan Literatur.
- Pemetaan Standar ISO/IEEE.
- Daftar Referensi dan Daftar Pustaka.
- Rangkuman Materi Pendukung.

**Catatan:** Dokumen standar lengkap harus dibedakan dari artikel, abstrak, atau publikasi yang hanya membahas standar tersebut.

## 3. Member 3 — Test Design / Test Case Designer

**Fokus Utama:** Analisis fitur dan perancangan skenario pengujian.

### Materi yang Perlu Dipelajari
1. Pengertian Black Box Testing.
2. Teknik Equivalence Partitioning (EP).
3. Teknik Boundary Value Analysis (BVA).
4. Perbedaan Test Scenario dan Test Case.
5. Test Data, Expected Result, dan Actual Result.
6. Cara menyusun test case yang baik.

### Sumber Belajar dan Referensi
- Google: Black Box Testing Techniques.
- Google: Equivalence Partitioning with Examples.
- Google: Boundary Value Analysis with Examples.
- Google: How to Write Software Test Cases.
- Materi perkuliahan tentang software testing.

### Tanggung Jawab
1. Menganalisis fitur aplikasi yang akan diuji.
2. Mengidentifikasi kondisi dan variasi input yang perlu diuji.
3. Menyusun test scenario dan test case.
4. Menerapkan teknik Equivalence Partitioning dan Boundary Value Analysis.
5. Menyiapkan data pengujian valid dan tidak valid.
6. Memastikan test case mudah dipahami dan dapat dijalankan.
7. Meninjau rancangan pengujian sebelum pelaksanaan.

### Target Hasil Pekerjaan
- Analisis Fitur.
- Test Scenario.
- Test Case.
- Test Data.
- Analisis Equivalence Partitioning dan Boundary Value Analysis.

---

## 4. Member 4 — Test Execution, Automation & Defect Management

**Fokus Utama:** Pelaksanaan pengujian manual, otomatisasi, dan pengelolaan bug.

### Materi yang Perlu Dipelajari
1. Pengertian dan tahapan Manual Testing.
2. Pengertian Functional Testing.
3. Dasar Selenium WebDriver.
4. Konsep Automation Testing.
5. Test Execution dan pencatatan hasil pengujian.
6. Bug Reporting dan Bug Life Cycle.
7. Perbedaan Manual Testing dan Automation Testing.

### Sumber Belajar dan Referensi
- Google: Manual Testing for Beginners.
- Google: Selenium WebDriver Tutorial for Beginners.
- Dokumentasi resmi Selenium: https://www.selenium.dev/documentation/
- Google: Software Bug Life Cycle.
- Google: Manual Testing vs Automation Testing.

### Tanggung Jawab
1. Menjalankan manual testing berdasarkan test case yang telah disusun.
2. Mempelajari dan menerapkan Selenium pada test case yang dipilih.
3. Mencatat hasil pengujian berupa Pass atau Fail.
4. Mengumpulkan screenshot dan bukti pengujian.
5. Mengidentifikasi dan melaporkan bug.
6. Melakukan retesting apabila tersedia perbaikan.
7. Membandingkan hasil manual testing dan automation testing.

### Target Hasil Pekerjaan
- Hasil Manual Testing.
- Script Selenium.
- Hasil Automation Testing.
- Bug Report.
- Hasil Retesting.
- Analisis Perbandingan Manual dan Automation Testing.

# Kolaborasi Tim

Walaupun setiap anggota memiliki tanggung jawab utama yang berbeda, seluruh anggota wajib:

1. Memahami dasar-dasar software testing.
2. Aktif berkomunikasi dan memberikan perkembangan pekerjaan.
3. Membagikan hasil belajar dan referensi yang relevan.
4. Saling membantu dan meninjau pekerjaan anggota lain.
5. Mendokumentasikan hasil pekerjaan di repository GitHub.

Setiap anggota bertanggung jawab memahami role masing-masing dan menyelesaikan target pekerjaan yang telah disepakati bersama.
